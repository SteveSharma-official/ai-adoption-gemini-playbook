# Contributing

1. Keep data synthetic. Use `shared/scripts/generate_datasets.py`; never commit real exports.
2. Every lab keeps the proof sequence: starter, solution, lab-changes (break it safely), and a fix that passes again.
3. Run `python -m pytest -q` before opening a pull request.
4. Use the terminology in docs/terminology.md exactly as the book does.
5. Do not claim validation you have not run. Use the status vocabulary in docs/validation-status.md.
6. Australian English. No em dashes.
